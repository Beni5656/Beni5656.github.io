CS180 · Programming Project #1

Images of the Russian Empire

Colorizing the Prokudin-Gorskii photo collection: splitting each glass plate into its three exposures, aligning them, and stacking them back into colour.

OverviewWhat we are starting from

Each digitized glass plate is one tall greyscale image holding three exposures of the same scene, taken through a blue, a green, and a red filter, stacked B, G, R from top to bottom. The job is to cut the plate into thirds and translate the green and red frames onto the blue one until they line up, turning three greyscale exposures into one colour photograph. Only translation is allowed, an (x, y) shift, no rotation or scaling.

Part 1Scoring a candidate alignment

To pick an offset, every candidate shift is scored and the best one is kept. The simplest score is the L2 norm, the Euclidean distance between the two overlapping patches: 

def euclidean_distance(im1, im2):
    return np.sqrt(np.sum(np.sum((im1 - im2) ** 2)))

Lower is better, zero is a perfect match. The other standard metric is normalized cross-correlation (NCC), the dot product of the two patches after each is mean-subtracted and scaled to unit length: 

def normalized_cross_correlation(im1, im2):
    a = im1 - np.mean(im1)
    b = im2 - np.mean(im2)
    return -np.sum(a * b) / (np.linalg.norm(a) * np.linalg.norm(b))

NCC helps when the two images differ by a constant brightness or gain, since normalising removes exactly that difference.

Neither metric is run on raw pixel brightness in my final code. The project itself flags the problem: the Emir of Bukhara's channels do not share the same brightness values, since a strong blue robe is bright in the blue exposure and dark in the red one. So both align() and pyramid() first run each frame through a Sobel filter and compare gradient magnitude instead of raw intensity. A Sobel filter responds to edges, not brightness, so the outline of the robe lines up correctly even though the fabric itself does not.

Every candidate offset is produced with np.roll, which wraps pixels around the edge. That wrapped strip is discarded before scoring by cropping a margin off all four sides and comparing only the interior, per the assignment's own advice to ignore borders when scoring.

Part 2Single-scale alignment

The base case is an exhaustive search: try every offset in a window of [-15, 15] pixels in both directions, score each with the metric above, and keep the best. That is 31 × 31 = 961 candidates per channel: 

def align(channel1, channel2, num1, num2, margin):
    grad1 = sobel(channel1)
    grad2 = sobel(channel2)
    cropped2 = grad2[margin : -margin, margin : -margin]

    for i in dx:                                   # horizontal offsets, -15..15
        for j in dy:                               # vertical offsets, -15..15
            row_shift = np.roll(grad1, j, axis=0)
            col_shift = np.roll(row_shift, i, axis=1)
            cropped1  = col_shift[margin : -margin, margin : -margin]
            score = euclidean_distance(cropped1, cropped2)
            # keep the offset with the lowest score

Part 3Multi-scale pyramid alignment

The full-resolution plates need offsets as large as 177 pixels, so a ±15 window cannot reach the answer, and widening it to ±200 would mean roughly 161,000 candidates scored over an 11-megapixel frame. Instead, pyramid() halves the image repeatedly until it is under 200 pixels tall, runs the exhaustive ±15 search there, then walks back up, doubling the inherited offset at each step and searching only a ±5 correction around it: 

def pyramid(channel1, channel2):
    if channel2.shape[0] < 200:
        return align(channel1, channel2, 15, 15, margin=...)      # coarsest level
    else:
        dx, dy, score = pyramid(rescale(channel1, 0.5),
                                rescale(channel2, 0.5))           # recurse
        dx *= 2
        dy *= 2                                                   # scale back up
        col_shift = np.roll(np.roll(channel1, dy, axis=0), dx, axis=1)
        corrected_dx, corrected_dy, new_score = align(col_shift, channel2, 5, 5, margin=...)
        return dx + corrected_dx, dy + corrected_dy, new_score

A 3200-pixel-tall frame takes about six halvings to get under 200, so the total cost is one 961-candidate pass on a tiny image plus six 121-candidate passes, dominated by the single pass at full resolution. Aligning both channels of a full plate (9,627 × 3,702 pixels) takes about 44 seconds, comfortably under the one-minute-per-image target, using the same parameters for every image.

Emir is the one image the assignment itself names as a hard case, and it is the one image both raw-pixel metrics get wrong: its robe is bright in one exposure and dark in another, so matching pixel values directly compares a light region to a dark one. NCC does not fix this since it only removes a single global brightness/gain difference, not a per-material one, and lands 588 pixels off. Church fails plain L2 because its large flat sky and water match almost as well at the wrong offset as the right one; NCC's normalisation corrects that case.
